After the tutorial

What to set up before real use, how to keep the CSOC current, the gaps these docs do not cover yet, and where to get help.

Before real use

  • Connect your identity provider. Broker Keycloak to your campus single sign-on so that people sign in with their institutional accounts. See Add your institution's sign-in to Keycloak.
  • Configure backups. The bootstrap configures none. Back up Keycloak's database and each commons' database before they hold anything you need to keep. See What this setup is not.
  • Plan for data. Turn on persistence for each commons' database, or use an external database, and configure a data bucket before anyone uploads files. See Where the data lives.
  • Pin image tags. Replace the branch tags of the CSOC images with release tags. See Images and pinning.
  • Plan the Kubernetes version. The default version is in EKS extended support, the largest avoidable cost. See Upgrade Kubernetes.
  • Set a budget alert. See Cost.
  • Review the allowed addresses. Replace individual addresses with your campus and VPN ranges. See Allow a new IP address.
  • Have the setup reviewed. Give your security and compliance reviewers Security, cost and responsibilities and Architecture, and agree on what data each commons may hold.

Keep it up to date

Upgrades are not automated. Test each change on a CSOC that holds nothing important first.

  • Infrastructure. Resume the environment in the wizard, press Plan again, and read the plan. Apply only changes you expect; an apply that destroys or replaces resources asks for the environment name.
  • The CSOC portal and API. On the Install step, open Advanced, press Bootstrap, enter the new tags under Images, and run the bootstrap and the finish again.
  • Commons. Each commons is a Helm release of the gen3 chart. Before you change its version, read the gen3-helm release notes and the Gen3 documentation.

Upgrade Kubernetes

The cluster runs Kubernetes 1.33, which bills at the EKS extended-support rate, $438 a month instead of $73 a month. The wizard has no field for the version. The version is the Terraform variable eks_version in gen3-terraform's examples/csoc/variables.tf (default "1.33"). To change it:

  1. Check the Amazon EKS Kubernetes release calendar for the target version. EKS upgrades one minor version at a time, so 1.33 goes to 1.34, then 1.35.
  2. Terminal In a local gen3-terraform checkout, set the default of eks_version to the next minor version, and start the wizard with TERRAFORM_MODULES_DIR pointing at that checkout (see For developers).
  3. Resume the environment, press Plan again, and check that the plan updates the cluster in place (~N to update) rather than replacing it.
  4. Press Apply. Repeat for each minor version.

Test this on a CSOC that holds nothing important first: changing the version this way is a developer procedure, not a wizard feature.

Add more commons

Deploy further commons into the CSOC's cluster from the portal: on the success page press Deploy Another, or open Deploy a new Gen3 instance. Give each one its own release name, such as commons-b, and hostname, such as commons-b.csoc.example.org.

Known gaps

These topics are not covered by these docs yet, or the behavior has not been checked:

  • Data uploads. Creating a data bucket for a commons and giving Fence access to it.
  • Agents in other clusters. Connecting an agent in a cluster in another AWS account to the CSOC's agent endpoint.
  • Re-applying user.yaml. Whether Update Deployment re-runs the commons' useryaml job, and how to re-run it if not.
  • Identity brokering. The Keycloak steps in Add your institution's sign-in to Keycloak are general Keycloak guidance and have not been tried end to end with a CSOC.
  • The EKS public endpoint. Restricting it to CIDR ranges, or closing it; the configuration sets eks_public_access, which the wizard does not expose.
  • EKS secrets encryption. What EKS applies by default to Kubernetes Secrets in this configuration.
  • Commons cost. The cost of a commons has not been measured.
  • Image and module versions. docker-compose.workshop.yml pins the images to the branch tag feat_csoc-bootstrap-wizard and the Terraform to the branch feat/csoc-bootstrap-master, not to releases.
  • The Kubernetes version. There is no wizard field for it; see Upgrade Kubernetes.
