Edit a commons' user.yaml

Change who may do what in a commons after it is deployed.

When you need this

When you add a user to a commons, remove one, or change their permissions. The portal does this by reopening the deployment wizard with the commons' current settings.

Before you start

  • Write the new user.yaml. The tutorial's file is in Prepare the user.yaml, and the user.yaml guide describes the format.

Steps

  1. CSOC portal Open the Projects page, https://portal.csoc.example.org/projects.
  2. Find the commons, for example commons-a, and press Edit. The Gen3 deployment wizard opens with the release's current values loaded.
  3. Go to the Auth step and replace the whole content of Custom Role Definitions (YAML format) with the new user.yaml.
  4. Go to the Deploy step, check the summary, and press Update Deployment.

Check it worked

The portal shows Deployment Updated!. Sign in to commons-a.csoc.example.org as an affected user and check that their access changed.

The commons applies user.yaml with a Kubernetes Job named useryaml in its namespace. Terminal To see when it last ran:

bash
aws eks update-kubeconfig --name <csoc-name> --region <your-region> --profile <your-aws-profile>
kubectl -n commons-a get job useryaml

If it fails

  • Access did not change, and the useryaml job's completion time is older than the update: the job did not run again. Re-running it is listed in Known gaps.
  • A user still has no access: the email in user.yaml must match the email Keycloak passes to Gen3 exactly.
  • Update Deployment shows Deployment Failed with Token verification failed: reload the page and press Update Deployment again.
