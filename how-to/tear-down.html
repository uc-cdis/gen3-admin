Tear down a CSOC

Remove the CSOC, its commons and its infrastructure, and optionally the hosted zone and the state bucket.

Wizard step DoneTime 10–15 minutes

A teardown permanently deletes all data

Every commons in the cluster is deleted with it: its databases, its volumes and its Kubernetes Secrets, with no way to recover them. The CSOC's secrets in Secrets Manager are deleted without a recovery window, and Keycloak's users and settings go with its database. The bootstrap configures no backups.

When you need this

When you no longer need a CSOC, for example after a test, and want to stop its costs ($720–800 a month in us-east-1).

Before you start

  • Back up everything you want to keep: commons databases, data files, and the users and settings in Keycloak.
  • Terminal Sign in so that at least 45 minutes are left on your SSO sign-in. Otherwise the wizard stops before it starts, with the message "A teardown takes 10–15 minutes, up to 45, and stops part-way if the sign-in ends first."
  • Open the wizard at localhost:3000/bootstrap and resume the environment if needed (see Resume after closing the tab).

Steps

  1. On the Done step, press Tear down in the banner. You can also open Advanced under the run log and press Tear down….
  2. For test environments, leave Force: don't wait for anything graceful on, the default. It deletes nodes and disks immediately instead of shutting them down cleanly. Turn it off only if workloads must stop gracefully, which makes the uninstall slower.
  3. Choose whether to delete the zone:
    • If you will not reuse csoc.example.org, select Also delete the hosted zone and its delegation. Under Parent zone reached with, choose These credentials (the default) if the parent zone is in this account, Profile: … for another account, or Nothing: I remove the NS records myself if central IT manages it (then ask them to remove the NS record set).
    • If you will reuse it, leave the box off.
  4. Select Also empty and delete the state bucket only if you will not come back to this environment. The bucket is deleted only after every environment in it is destroyed.
  5. Type the CSOC name, for example csoc-dev, to confirm, and press Tear down.

The teardown panel lists its steps with their state. Each starts only after the previous one succeeds:

  1. Uninstall the CSOC removes what the bootstrap added outside Terraform: load balancers, volumes, Karpenter's nodes, DNS records and secrets. It takes 2–10 minutes.
  2. Destroy the infrastructure runs terraform destroy ("terraform destroy: the cluster, VPC, Squid, IAM roles and the certificate. About 5 minutes.").
  3. Delete the hosted zone, with the CSOC's certificate and the NS records in the parent zone, if selected.
  4. Delete the state bucket, if selected.

Check it worked

Uninstall in progressRemoving the load balancers, volumes, nodes, DNS records and secrets the install added. A few minutes.
Destroy in progressDeleting the infrastructure. About 5 minutes; up to 30 if AWS is slow to release network interfaces.
Torn downTerraform destroyed everything it created. Below is what is left outside it.Buttons: [Provision again] [Start over]

Below the banner, What is left checks AWS for the CSOC's certificate, the hosted zone and the state bucket, each with its own delete button. When nothing is left, the banner reads Back to a blank account.

The commons commons-a is removed with the cluster. Its ACM certificate, which the portal requested, is not; it is free, and you can delete it in the ACM console.

Time

10–15 minutes from Tear down to Torn down: 2–10 minutes for the uninstall, then about 5 minutes for the destroy; normal up to 25 minutes.

For what the uninstall removes and in what order, see Teardown in Architecture.

If it fails

  • No progress for 30 minutes: open the run log and search for DependencyViolation. It names the resource AWS will not delete yet, for example a network interface or a security group that something still uses. Do not change the runner scripts or stop the run; wait, then see Tear down troubleshooting.
  • A banner reports a failure: see Tear down troubleshooting.
