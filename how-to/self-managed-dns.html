Use DNS you manage yourself

Run the CSOC without a Route 53 zone, creating its DNS records at your own DNS host.

When you need this

When your institution will not delegate a subdomain to the CSOC account and keeps the CSOC's hostnames in its own DNS. If delegation is possible, use it instead (Request DNS delegation): with self-managed DNS, the bootstrap does not install external-dns and the CSOC cannot write validation records, so every commons also needs its records created by hand.

Before you start

  • Arrange with whoever manages your DNS to add four CNAME records during the tutorial, two to validate the certificate and two for the hostnames, and more for each commons later.

Steps

  1. On the Setup step, under DNS for the hostnames, choose I manage DNS myself. The wizard then does not create or check a hosted zone.
  2. Continue through Review and Provision as in the tutorial.
  3. On the Certificate step, press Request. When the banner says Create the validation records in your DNS, Your DNS provider create one CNAME record for each row of the table, with the name and value shown.
  4. Press Check now, or wait: the page checks every 10 seconds. When public DNS answers, the banner says Records found; waiting for ACM to issue, and the wizard moves on once the certificate is issued.
  5. Run the Install step as in the tutorial. After the finish, the Done step shows two CNAME records under "Create these records where your DNS is hosted", one for each hostname, both pointing at the load balancer. Your DNS provider Create them.

Check it worked

The banner reads CSOC is ready, and portal.csoc.example.org and auth.csoc.example.org open the CSOC. Keep the validation records in place: ACM uses them to renew the certificate (DNS validation).

If it fails

  • The banner stays at Create the validation records in your DNS: public DNS does not answer for the records yet. Check with dig CNAME followed by the record name.
  • See Certificate troubleshooting.
