Troubleshooting

Every known problem in one place, grouped by tutorial page. Each tutorial page shows the same rows in its own Troubleshooting section.

Common to every step

AWS session expired

A yellow AWS session expired box disables every button. Run aws sso login --profile campus-sso, then press Check again.

Closed the tab, or the page reloaded

Nothing is lost. See Resume after closing the tab.

"No such name" (NXDOMAIN) on some networks

If your computer looked up a hostname before its record existed, your network's DNS resolver can keep answering "no such name" for a while. The wizard's zones use a 60-second negative-caching time to keep this short. Wait 5 minutes, or switch your computer to a public resolver such as 1.1.1.1.

Using kubectl

Some checks below use kubectl. In a terminal, connect it to the cluster with aws eks update-kubeconfig --name <csoc-name> --region us-east-1 --profile csoc-admin.

Read the log before you stop a run

Stopping a run leaves it stopped, and an interrupted apply leaves the environment partial. Most long waits are expected; the time on each page says how long is normal.

Setup

These rows also appear on Setup.

What you seeWhat it meansWhat to do
Yellow box: AWS SSO session expired, with a commandYour SSO sign-in ran out. The Setup step cannot check anything until you sign in.In a terminal, run the command shown, for example aws sso login --profile <your-sso-profile>, then press Retry in the box.
The blue box shows the wrong accountAuto-detect used your default credentials, or the profile points at another account.Choose Select AWS profile and the profile for the CSOC account.

Tear down

These rows also appear on Tear down.

What you seeWhat it meansWhat to do
Banner: The uninstall failedRemoving what the bootstrap added did not complete. The CSOC is still recorded.Press Retry teardown with Force. It retries with the Force setting you chose, which is on unless you turned it off. If the cluster cannot be reached at all, press Destroy anyway…, which lists what may be left behind and asks for the name.
Banner: The destroy failedThe environment is partial; some resources still exist.Search the log for DependencyViolation to see which resource blocked it, then press Retry teardown. It continues where it stopped. A retry does not delete the state bucket; delete it afterwards from What is left.
A prompt to sign in again before the teardown starts"A teardown takes 10–15 minutes, up to 45, and stops part-way if the sign-in ends first."In a terminal, run aws sso login --profile <your-sso-profile>.
The state bucket is not deletedAnother environment in it is not destroyed, or it holds other objects.Destroy the other environments first, or keep the bucket.
