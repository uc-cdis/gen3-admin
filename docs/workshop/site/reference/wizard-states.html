Wizard states and banners

Every banner the wizard can show, what it means, and the buttons it offers.

How the banner is derived

The banner shows the next step, based on what exists, the last run's result, and the certificate's status. The wizard keeps one record per environment in the state bucket, with a settled status (what exists) and the last run; it also takes into account any blocking problem, such as an expired sign-in, and a GitOps pull request. A failed or stopped run never erases the settled status before it, so every failure can be retried from where it stopped.

Settled statusMeaning
newRegistered by Provision, never planned.
plannedA plan exists; nothing is applied.
appliedThe infrastructure exists; the CSOC is not installed.
bootstrappedThe bootstrap succeeded; the finish has not.
installedThe CSOC is ready.
partialAn apply or a destroy stopped part-way; some resources exist.
destroyedTerraform destroyed everything it created.
Last run statusMeaning
runningA run is in progress. The banner offers only Stop this run.
succeededThe run finished, and the settled status moved on.
failedThe run ended with an error. Its log is shown, with the Error: lines first.
stoppedSomeone pressed Stop this run.
lostThe API restarted while the run was in progress, so its end was not recorded.

Buttons that the banner does not offer, such as running the bootstrap or the finish again, or tearing down a working CSOC, are under Advanced below the run log.

Banner colors: blue in progress or informational, green complete, yellow needs your attention, red failed, gray nothing created or torn down.

A stopped bootstrap or finish says "The log below shows where it stopped" in its banner; a failed one says "The log below says what went wrong".

Checks before a run starts

  • Destructive changes. An apply whose plan destroys or replaces existing infrastructure asks for the environment name. So does Destroy anyway… after a failed uninstall, which first lists what may be left behind.
  • Remaining sign-in time. An apply or a teardown with less than 45 minutes left on your SSO sign-in, or a bootstrap or a finish with less than 15, first asks you to sign in again and shows the aws sso login command.
  • One run per environment. The API refuses a second run while one is recorded as in progress, from any browser tab or computer.
  • Certificate before bootstrap. The bootstrap needs an issued certificate. Until there is one, the banner leads to the certificate.
  • A failed plan on a running CSOC. If the infrastructure already exists, a failed plan or init is shown as a note beside the real next step.

An expired sign-in blocks everything

Whatever the state, a yellow AWS session expired box with the aws sso login --profile … command disables every button until Check again succeeds. A run that cannot start, for the same reason or because a role cannot be assumed, says so in a red box and changes nothing.

A missing or undelegated zone

A Route 53 zone that is missing or not delegated is fixed from the banner, on whichever step you are on. It blocks only what needs the zone; a teardown can still run.

Screen rules

  • Next action. The banner holds the next action, and the page below it shows the details. Tearing down is offered on the Done step, under Advanced, and in the banner only where it is a reasonable way out, such as a half-built environment.
  • Stepper. It marks what exists, so after a teardown the Provision and Install steps are open again.
  • Run log. It is open while a run is in progress or right after one failed, with the Error: lines shown above it, and folded otherwise. Advanced under the log (not Advanced Options on Setup) offers single operations: Init, Plan, Apply, Bootstrap, Finish install and Tear down…; only the ones the state allows are enabled.
  • Teardown panel. It shows the form before a teardown, the live list of steps while one runs or where it stopped, and, when it is done, only What is left, checked against AWS when the page loads.
