Security, cost and responsibilities

For the people who approve a CSOC: what it stores and where, what is reachable from the internet, why it needs administrator rights, what it is not designed for, what it costs, and who is responsible for what.

Why administrator rights

The bootstrap creates IAM roles and policies, a VPC with its gateways and routes, an EKS cluster with Fargate and EC2 capacity, an AWS Lambda function, CloudWatch log groups, load balancers, Route 53 zones and records, ACM certificates, Secrets Manager secrets and S3 buckets. Creating IAM roles alone requires broad permissions, so the operator needs an administrator role in the account. Use an account dedicated to the CSOC, so that these rights cover nothing else.

The running CSOC does not use the operator's rights: each component uses its own IAM role (see IAM roles). The operator needs administrator rights again for anything done from the wizard: changing the allowlist, upgrading, resetting the administrator password and tearing down.

The IP allowlist

The CSOC's load balancers accept connections only from the address ranges in Allowed addresses, plus the cluster's own outbound address. This covers the CSOC portal, Keycloak and the agent endpoint. The allowlist is a network control in addition to sign-in, not instead of it. Plan which ranges you need: your operators' VPN, your campus network's outbound ranges, and any partner networks. See Allow a new IP address.

Identity

The install creates one local Keycloak user, admin. For real use, connect Keycloak to your institution's identity provider instead of creating local users; Keycloak supports identity brokering with SAML 2.0 and OpenID Connect providers, which includes campus single sign-on and federations such as InCommon. See Connect your institution's sign-in. Each commons that uses Use CSOC login then accepts the same identities.

Inside a commons, permissions come from its user.yaml, which maps each user's email to policies. The tutorial's user.yaml gives one email full control of the commons and gives everyone else nothing. Review each commons' user.yaml as part of its data access approval; see Edit a commons' user.yaml.

What this setup is not

  • Not hardened for regulated data as delivered. It has not been assessed for controlled-access data, protected health information, or frameworks such as NIST SP 800-171 or HIPAA. Holding such data requires your own security review and additional controls.
  • No backups are configured. The bootstrap does not back up Keycloak's database, the CSOC API's volume, or any commons database, and a commons' local database is not even persistent unless you turn on persistence. Configure backups before you rely on the CSOC, for example CloudNativePG backups and EBS snapshots.
  • Not highly available. The cluster spans three availability zones, but Keycloak, its database and the CSOC portal each run as a single instance. A node failure interrupts them until Kubernetes starts them elsewhere.
  • Not a managed service. Upgrades of the cluster, the charts and the images are the operator's responsibility; see Keep it up to date.

Shared responsibility

AWS is responsible for the security of the cloud, such as its data centers and managed services; you are responsible for security in the cloud, including configuration, access and data (AWS shared responsibility model). Within your institution:

AreaResponsible
The AWS account, its budget, and organization policiesOwner, with the cloud account administrators

Keeping access to the wizard, the state bucket and an administrator role, and handing it overOperator, with the owner

Cost

A running CSOC costs $720–800 a month in us-east-1, before commons and data transfer, on the default Kubernetes version 1.33. That version left EKS standard support on July 29, 2026, so the control plane is billed at the extended-support rate of $0.60 per hour, $438 a month instead of $73 a month, until extended support ends on July 29, 2027. On a Kubernetes version in standard support (1.35 or later; 1.34 leaves standard support on December 2, 2026) the CSOC costs $360–440 a month in us-east-1, before commons and data transfer. Sources: the Amazon EKS Kubernetes release calendar and Amazon EKS pricing. The Rough Monthly Cost Estimate on the wizard's Review step shows the same figure, $720–800/month.

What a commons adds

Each commons adds its own resources to the bill. Their size depends on the services you enable and on use:

  • EC2 nodes that Karpenter starts for the commons' services, the largest part.
  • An Application Load Balancer, about $16 a month in us-east-1 plus capacity units, and its public IPv4 addresses.
  • An EBS volume for the local database, if you turn on persistence, or a managed database if you use an external one.
  • S3 storage and requests for data files, once you configure a data bucket.

Check the actual figures in AWS Cost Explorer a day after you deploy, filtered by the commons' resources.

What remains after teardown

A teardown removes everything Terraform and the bootstrap created. These remain unless you remove them; the wizard's What is left list offers to delete the first three:

  • The hosted zone csoc.example.org, $0.50 a month, if you did not select it for deletion.
  • The CSOC's ACM certificate, which is free, if the zone was kept.
  • The state bucket gen3-csoc-csoc-dev-111122223333, a few cents a month, if you did not select it for deletion.
  • Each commons' ACM certificate, which the portal requested. Certificates are free; delete them in the ACM console.

Campus realities

  • The parent domain belongs to central IT. At most universities, delegating csoc.example.org needs a ticket and takes days. Send the request early; Request DNS delegation has a template.
  • Service Control Policies can block services. AWS organizations can limit Regions or services with Service Control Policies. Ask your cloud administrators to confirm that EKS, Fargate, EC2, AWS Lambda, Route 53, ACM, Secrets Manager and IAM role creation are allowed in us-east-1. An SCP denial looks like an access error even with administrator rights.
  • Campus and VPN outbound addresses. The allowlist needs the public addresses your traffic leaves from, which are not your computer's local address. Ask your network team for the outbound ranges of the campus network and the VPN.
  • Short sign-in sessions. The wizard asks for at least 45 minutes left on your AWS sign-in before an apply or a teardown. If your institution sets short sessions, sign in again just before each long step.

Kubernetes permissions of the CSOC API

The CSOC API's service account has a cluster role that can create, change and delete namespaces, Secrets, ServiceAccounts, ConfigMaps, Deployments and other workloads, roles and role bindings (including cluster-wide ones), Services, ingresses and Jobs, and can exec into pods. It uses these to install agents. In effect, the CSOC API is an administrator of its own cluster, so access to the CSOC portal should be treated as administrative access.

Encryption at rest

  • Volumes. The default storage class (gp3) creates encrypted EBS volumes, so Keycloak's database and the CSOC API's volume are encrypted, with the AWS managed key. Node root volumes are encrypted too.
  • State bucket. Encrypted by default.
  • Secrets Manager. Encrypted with the AWS managed key.
  • Kubernetes Secrets. The configuration does not set up envelope encryption with a customer managed KMS key. What EKS applies by default is described in the Amazon EKS documentation.

Audit logs

  • VPC flow logs are off by default (vpc_flow_logs = false). See VPC flow logs to enable them.
  • EKS control-plane logs, including the Kubernetes audit log, are not enabled. See control plane logging.
  • AWS API activity is recorded by AWS CloudTrail if your account or organization has it on; the bootstrap does not configure it.
  • The wizard's runs are recorded in the state bucket, with their logs.

Outbound traffic

The cluster reaches the internet only through Squid. Each Squid instance, as it boots, clones the uc-cdis/cloud-automation repository from GitHub (branch master) and uses its default allowlist files: web_whitelist, about 190 exact hostnames, and web_wildcard_whitelist, about 120 domain wildcards. The wildcards include all of .amazonaws.com, .github.com, .githubusercontent.com, .quay.io, .docker.io and .gen3.org, package repositories such as .anaconda.org, .bioconductor.org and .cpan.org, and the domains of other research data commons. The list therefore allows far more than the CSOC needs, and it changes when that repository changes. The configuration can point at another repository or files (whitelist_repo, web_whitelist_file, web_wildcard_whitelist_file); the wizard does not expose them.

SSH access to nodes

Each EC2 node that Karpenter starts runs a startup script that appends the public keys in cloud-automation's files/authorized_keys/ops_team to the node's ec2-user account, and every node carries the security group ssh_eks_<csoc-name>, which allows SSH from 0.0.0.0/0. The nodes have no public addresses, so this allows SSH from inside the VPC only, by the holders of those keys. Reviewers should decide whether to remove the keys and the rule; both are in the gen3-terraform eks module.

Third-party sources

Building, installing and running the CSOC downloads from these sources:

  • quay.io (quay.io/cdis/…): the wizard's images (csoc-api, csoc-bootstrap-frontend, csoc-terraform), and the CSOC, agent and Gen3 images.
  • Docker Hub: tecnativa/docker-socket-proxy, on your computer (and hashicorp/terraform if you build the runner from source).
  • public.ecr.aws: the busybox image.
  • GitHub: the gen3-terraform configuration and modules (branch feat/csoc-bootstrap-master), cloud-automation (Squid's startup scripts and allowlist), and the Keycloak operator's manifests (keycloak/keycloak-k8s-resources).
  • Helm repositories: charts.external-secrets.io, aws.github.io/eks-charts, kubernetes-sigs.github.io/external-dns, kubernetes-sigs.github.io/aws-ebs-csi-driver, cloudnative-pg.github.io/charts, argoproj.github.io/argo-helm (GitOps only) and helm.gen3.org.
  • checkip.amazonaws.com, to find the cluster's outbound address.

The wizard on your computer

The wizard's API acts with your AWS administrator credentials, and it does not ask anyone to sign in: every request it receives is treated as coming from you. That is acceptable only because it listens on 127.0.0.1, so only programs on your own computer can reach it. It starts containers through a proxy that allows container and image operations and blocks the rest of the Docker API. Do not change the port bindings, do not run the wizard on a shared or remote machine, and stop it (docker compose -f docker-compose-bootstrap-csoc.yml down) when you are not using it.

Administrator accounts

Two administrator logins exist: the CSOC's admin user in csoc-realm, and Keycloak's own administration login, stored in Secrets Manager. Neither has a second factor by default. Keycloak supports one-time passwords as a required action and in authentication flows; see the Keycloak Server Administration Guide.

Reporting vulnerabilities and license

The gen3-admin repository has no security policy file. Do not report a vulnerability in a public GitHub issue; contact the maintainers privately, for example with GitHub private vulnerability reporting if the repository has it enabled. gen3-admin is licensed under the Apache License 2.0.
