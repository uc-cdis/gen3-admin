For developers

Settings and notes for people who change the wizard, the CSOC chart, the Terraform modules or these docs.

Build from source

Readers use the published images in docker-compose.workshop.yml. To build the wizard's API and frontend, and the runner image (gen3-terraform:latest), from the repository, use the development compose file:

bash
./scripts/build-terraform-image.sh
docker compose -f docker-compose-bootstrap-csoc.yml up -d --build

Developer settings

Put these in the repository's .env file, which is not committed, so that they survive restarts of the containers.

VariableEffect
TERRAFORM_MODULES_DIRUse a local gen3-terraform checkout, for example ~/src/gen3-terraform, for every plan, apply and destroy. Keep it set for the life of the environment: a destroy without it fails with "Module not installed".
CSOC_CHART_REPO, CSOC_CHART_REVISIONWhere a GitOps CSOC's Argo CD gets the CSOC chart, for testing chart changes from a fork or branch.

Destroy fails with "Module not installed"

The containers were restarted without TERRAFORM_MODULES_DIR for an environment created with it. Put it back in .env, restart the containers, and press Retry teardown.

The wizard does not ask anyone to sign in

The bootstrap API and frontend run with MOCK_AUTH=true: every request is treated as coming from an administrator, and the API acts with your AWS credentials. Keep their ports bound to 127.0.0.1.

In gen3-terraform

examples/csoc/ holds the CSOC's Terraform configuration: main.tf (the vpc and eks modules and the subnet for the Squid route-check function), bootstrap.tf (the IRSA roles, EKS access and the external-dns policy), variables.tf and outputs.tf. The modules are in tf_files/aws/modules/vpc and tf_files/aws/modules/eks. See uc-cdis/gen3-terraform.

The wizard's state rules

frontend/lib/wizardState.ts derives every banner. frontend/lib/wizardState.audit.test.ts runs every combination of status, last run, certificate, blocker and pull request through the rules; update it with any change to them, and update Wizard states.

These docs

The site in docs/workshop/site/ is generated from docs/workshop/site-src/. Edit the page sources there and regenerate:

bash
cd docs/workshop/site-src
node build.mjs
node check.mjs

The README in site-src has the style guide and the terminology the docs use.
