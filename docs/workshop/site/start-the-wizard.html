Start the wizard

Start the bootstrap wizard on your computer and open its first step.

Wizard step WelcomeTime about 1 minute

Goal

Run the wizard's three containers and open the Welcome step in your browser.

Steps

  1. Terminal In the gen3-admin directory, start the containers. The first time, after you pulled the images in Prerequisites, run:
    bash
    docker compose -f docker-compose.workshop.yml up -d
    On later runs, update the checkout and the images first:
    bash
    git pull
docker compose -f docker-compose.workshop.yml pull
docker pull quay.io/cdis/csoc-terraform:feat_csoc-bootstrap-wizard
docker compose -f docker-compose.workshop.yml up -d
  2. Terminal Check that all three containers are running: docker compose -f docker-compose.workshop.yml ps. It lists api, frontend and docker-proxy.
  3. Browser Open http://localhost:3000/bootstrap. On macOS you can run open http://localhost:3000/bootstrap.
  4. You see Welcome to the Gen3 CSOC Bootstrap, the list of what the wizard creates, and "Estimated time: about 40 minutes." Press Next at the top right.

Done when: the stepper shows Welcome · Setup · Review · Provision · Certificate · Install · Done and, after Next, the Environment Setup page is open.

When you are not using the wizard, stop it with docker compose -f docker-compose.workshop.yml down. Nothing in AWS changes when you stop it.

Expected result

The Welcome step is open in your browser.

Time

Under 1 minute from docker compose up to the Welcome step, when the images are already pulled.

What's happening

Three containers start on your computer: the wizard's web frontend, its API, and a proxy that lets the API start and watch other containers and blocks the rest of the Docker API. The frontend and the API listen only on your own computer, because the API acts with your AWS credentials and does not ask anyone to sign in. For each Terraform or install run, the API starts a new runner container and streams its log to the page.

Everything the wizard does is recorded in the state bucket you create on the next step, so you can close the tab and come back at any time. For the containers, ports and mounts, see The bootstrap wizard on your computer.

Keep the wizard on your own computer

Anyone who can reach the wizard's API can act with your AWS credentials. Keep the 127.0.0.1 port bindings in docker-compose.workshop.yml, and do not run the wizard on a shared server.

Troubleshooting

What you seeWhat it meansWhat to do
localhost:3000 does not load, or the page is blankThe frontend has not started, or it failed.Run docker compose -f docker-compose.workshop.yml logs frontend api and look for Error in the last lines.
port is already allocatedAnother program uses port 3000 or 8002.Stop that program (find it with lsof -i :3000), then run docker compose … up -d again.
Later, a red box: The init did not startThe runner image is missing, or AWS refused the credentials. Nothing ran.Check that docker images lists quay.io/cdis/csoc-terraform:feat_csoc-bootstrap-wizard; if not, pull it as in Prerequisites. Otherwise sign in again.
