Bootstrap a Gen3 CSOC in your AWS account

These docs take you from an empty AWS account to a running CSOC, the control plane that deploys and manages Gen3 data commons, and then to a first Gen3 commons deployed from it.

To a running CSOC about 40 minutes in the wizardFirst commons about 12 minutes from Deploy

You run a bootstrap wizard on your own computer. It uses your AWS credentials to create the network, the Kubernetes cluster, the certificate and the DNS records, and it shows you what it will create before it creates anything. When it finishes, you sign in to the CSOC and deploy a Gen3 commons from it. If you are new to the terms, start with What is a CSOC?

Who these docs are for

They are written for research-IT and research-computing groups, at large universities and at smaller research institutes, and for three readers in particular:

Deciding whether to adoptWhat a CSOC is, who it suits, and the roles involved. Running itThe prerequisites, then the tutorial step by step, then the how-to guides. Reviewing security and complianceWhat is exposed, where secrets live, why administrator rights are needed, and the shared responsibilities.

What you'll build

  • An S3 state bucket that holds the Terraform state and a record of every change.
  • A Route 53 hosted zone for a subdomain such as csoc.example.org. Your parent domain, example.org, delegates the subdomain to it: a record in the parent's DNS tells the internet which name servers answer for the subdomain.
  • A VPC (private network) across three availability zones, with a NAT gateway (lets private machines reach the internet without being reachable from it) and Squid (a proxy that allows outbound traffic only to listed destinations).
  • An Amazon EKS Kubernetes cluster without fixed worker nodes: Karpenter starts EC2 nodes when workloads need them.
  • An ACM certificate for the CSOC's two hostnames, portal.csoc.example.org and auth.csoc.example.org.
  • The CSOC: the CSOC portal and Keycloak for sign-in, behind a load balancer that accepts only the IP addresses you allow.
  • A first Gen3 commons at commons-a.csoc.example.org, deployed from the CSOC and signed in to through the CSOC's Keycloak.

The Glossary defines every term.

How it fits together

The wizard and its API run in Docker on your computer. Everything else runs in your AWS account.

For the detail behind each box, read Architecture.

Conventions

  • Buttons look like Next and field labels look like CSOC Name. Both use the exact text on screen.
  • Wizard steps are named by their label in the wizard's stepper: Welcome, Setup, Review, Provision, Certificate, Install and Done.
  • One example runs through every page: the CSOC name csoc-dev, the subdomain csoc.example.org under example.org, the portal portal.csoc.example.org, Keycloak auth.csoc.example.org, the commons commons-a.csoc.example.org, the administrator jdoe@example.org, the address 203.0.113.7/32, and the Region us-east-1. Replace them with your own values; the worksheet collects them.
  • Commands and templates use placeholders such as <your-domain>, which you replace before running them.
  • A label such as Terminal marks a step that happens outside the wizard.
  • The banner under the wizard's stepper always says where you are and offers the next button to press. If a screenshot and the banner disagree, follow the banner.
  • About the screenshots: they come from an example run, so the account numbers, names and addresses in them belong to that run, and the stepper at the top of some of them uses different labels from the current wizard.
  • Press / to search. The moon button switches between light and dark themes, and pages print without the navigation.
